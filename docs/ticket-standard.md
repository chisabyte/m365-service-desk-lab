# Ticket and Evidence Standard

The repository uses one sequence of fictional Harbour Street Partners ticket IDs. A case first states **Problem or Request → Finding → Action → Result → Evidence**, then supplies the service-desk record. The short summary serves a recruiter; the record and linked images support technical review.

Each record identifies the synthetic user, category, user report or request, business impact, priority and its reason, questions asked (or the absence of a live interview), an initial hypothesis where applicable, evidence collected, troubleshooting, root cause or request driver, action, verification, simulated user communication, escalation, closure and related records. Priority is a lab triage judgement, not a production SLA.

Evidence rules:

- Staged faults and synthetic people are labelled as such.
- A written checklist or analyst note is attributed to that record; it is not presented as screenshot proof.
- Screenshot captions describe only visible content. A state screenshot does not prove the click or the person who made it.
- Later success must be tied to the specific row or visible user-context check that supports it.
- Simulated communication is labelled **not sent to a real user**.
- Licence and device-management limits are stated where relevant.
- Personal identifiers, tenant details and unrelated names are reviewed before evidence is copied into Git. Redactions in repository copies do not change the original evidence.
